# الفصل الحادي عشر: الأمان والصيانة

## إجراءات الأمان المطبّقة

| المجال | الإجراء |
|---|---|
| كلمات المرور | تُجزَّأ بـ bcrypt بتكلفة 12. سياسة: 10 أحرف على الأقل، وفيها حرف ورقم، وتُرفض الكلمات الشائعة. لا تُخزَّن ولا تُسجَّل نصاً أبداً |
| الجلسات | رموز JWT في كوكيز HttpOnly. الدور والمدرسة يُقرآن من قاعدة البيانات مع كل طلب. إبطال فوري لكل الجلسات عند تغيير كلمة المرور أو الدور أو القفل أو الحذف، وعند تسجيل الخروج |
| الحسابات الجديدة | كلمة مؤقتة مولَّدة، وإلزام بتغييرها قبل أي وصول للبيانات |
| التخمين | حد للمحاولات حسب عنوان IP والحساب، وقفل مؤقت بعد 5 محاولات خاطئة |
| المصادقة الثنائية | TOTP اختياري لكل مستخدم، ومنع إعادة استخدام الرمز |
| الصلاحيات | تُفحص في **الخادم** لكل طلب، ومعها نطاق البيانات (المدرسة، أو المدارس المسندة للمفتش) وملكية السجل المستهدف. مدير المدرسة لا يصل إلى مدرسة أخرى ولا يعدّل بيانات غيره |
| أدوار الاطلاع | مشرف المحافظة يُرفض له أي طلب تعديل في الوسيط وفي كل مسار |
| CSRF وإعادة التوجيه | طلبات التعديل مقبولة من نفس الموقع فقط، والتحويل بعد الدخول إلى مسارات المنصة الداخلية فقط |
| الملفات | فحص المحتوى الفعلي والحجم، وتخزين خاص، وتنزيل بصلاحية أو برابط موقّع مؤقت |
| روابط الخرائط | تحليلها في الخادم مقصور على نطاقات جوجل، وبحد لعدد التحويلات ومهلة زمنية |
| التصدير | الخلايا في ملفات CSV محمية من حقن الصيغ في Excel |
| التدقيق | سجل غير قابل للتعديل لكل إجراء حساس |
| رؤوس الأمان | سياسة أمان المحتوى (CSP)، ومنع التضمين في إطارات المواقع الأخرى، وتقييد أذونات المتصفح (الموقع للمنصة نفسها فقط) |

## البيانات الشخصية

- **المستودع عام:** كشوف المدارس التي فيها أسماء المدراء وأرقامهم **لا تُرفع إلى المستودع**، بل تُستورد من داخل المنصة فقط.
- **ملفات كلمات المرور:** الملفات التي تُنزَّل عند إنشاء حسابات المدراء **تُتلف بعد التسليم**.
- **الصور التوضيحية:** كل صور هذا الدليل مأخوذة من نسخة تدريبية منفصلة ببيانات موسومة «وهمية للعرض فقط». حُذفت البيانات التوضيحية من الموقع الفعلي (الترحيل 15).
- **أرقام هواتف المسؤولين** لا تُكتب في المستودع ولا في هذا الدليل، بل تُحفظ في حساباتهم داخل المنصة فقط.

## الصيانة الدورية

| المهمة | التكرار | الطريقة |
|---|---|---|
| نسخة احتياطية | أسبوعياً على الأقل، وقبل أي تحديث كبير | **الإدارة ← نسخة احتياطية**، وعلى الخادم `scripts/backup-db.sh` |
| فحص صحة النظام | عند أي شك | افتح `/api/health` |
| مراجعة الأمن والحوادث | شهرياً | **الإدارة ← الأمن والحوادث** و**سجل التدقيق** |
| مراجعة الحسابات | كل فصل دراسي | **المستخدمون**: عطّل حسابات من انتقلوا، وراجع من «لم يدخل بعد» |
| اكتمال البيانات | شهرياً | **الإدارة ← مركز التحكم** |
| بداية عام دراسي | أغسطس | تبدأ استمارة العام الجديد تلقائياً. أعلن للمدراء بدء الاختبار |

## استعادة نسخة احتياطية

- **Turso:** استورد ملف `.sql` إلى قاعدة جديدة باستخدام أداة Turso. ثم حدّث `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` في Vercel، ثم اضغط **Redeploy**.
- **خادم:** استخدم `scripts/restore-db.sh` مع ملف النسخة، بعد إيقاف الخدمة. التفاصيل في `DEPLOY.md`.

## تحديث المنصة

1. **التطوير والفحص:** تُطوَّر التعديلات على الفرع `khalilo-cs`، ثم تُشغَّل الاختبارات (`npm test` و`TEST_LIBSQL=1 npm test`) والبناء (`npm run build`).
2. **النشر:** يُرفع التعديل إلى GitHub، فينشره Vercel تلقائياً إن كان فرع الإنتاج مضبوطاً.
3. **الترحيلات:** أي ترحيل جديد يُطبَّق تلقائياً عند أول طلب بعد النشر.
