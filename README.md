# منصة رِفاد للمتابعة والجودة المدرسية — RIFAD

نظام إلكتروني متكامل لمتابعة وتقييم جودة المدارس في مديرية الجراحي بمحافظة الحديدة — الجمهورية اليمنية، وفق استمارة "التقييم الذاتي للمدارس" الصادرة عن مجلس الاعتماد الأكاديمي وضمان جودة التعليم (رجب 1447هـ – يناير 2026م).

المنصة منتج قابل للاستخدام الفعلي، وليس مجرد واجهة تجريبية. تشمل الواجهة الأمامية والخلفية، قاعدة بيانات، نظام الصلاحيات، رفع المستندات، التقييم الميداني، التقارير اليومية، لوحات المعلومات، خطط التحسين، التواصل الإلكتروني، ووضع العمل دون اتصال.

## 📦 ما يحتويه هذا الإصدار

| المكون | الوصف |
|--------|--------|
| `src/` | الكود المصدري الكامل (Next.js + TypeScript + Tailwind) |
| `prisma/schema.sql` | مخطط قاعدة البيانات كاملاً (جميع الكيانات والعلاقات والفهارس) |
| `prisma/seed/data.ts` | البيانات الأولية للمعايرة السبعة والمؤشرات (109 مؤشر) المستخلصة من الاستمارة الأصلية |
| `scripts/init-db.ts` | سكريبت تهيئة قاعدة البيانات وبذر البيانات الأولية |
| `.env.example` | مثال لمتغيرات البيئة المطلوبة |
| `public/fonts/` | خط أميري العربي للعناوين والنصوص |
| `public/brand/` | الشعار (SVG أفقي + رمز مفرد) ودليل الألوان |
| `docs/design/` | لوحات التصميم: نظام التصميم، الشعار، نماذج الشاشات (HTML مستقل) |

## 🛠️ لوحة الإدارة الشاملة

مدير النظام (`SUPER_ADMIN`) يملك تحكّماً كاملاً داخل المنصة عبر `/admin` — بلا حاجة
إلى تعديل الكود أو قاعدة البيانات يدوياً:

| التبويب | ما يمكن إدارته |
|---------|----------------|
| **المدارس** | إضافة مدرسة، تعديل بياناتها، أرشفتها، أو حذفها نهائياً |
| **المحافظات والمديريات** | إضافة/تعديل/حذف محافظة أو مديرية أو منطقة (الحذف مرفوض 409 إذا كانت مرتبطة بمدارس) |
| **المستخدمون** | تعديل الاسم والبريد والدور والمدرسة والمديرية، تعطيل الحساب أو قفله، وإعادة تعيين كلمة المرور |
| **المعايير والمؤشرات** | إضافة/تعديل/حذف المعايير والمعايير الفرعية والمؤشرات، ومراجعة مجموع الأوزان |
| **مقياس التقدير** | تعديل قيم التقدير 0–3 وأوصافها |

**قيود أمان مطبقة في الخادم:**
- لا يمكن إزالة صلاحية مدير النظام أو تعطيله إذا كان آخر مدير نشط في النظام.
- تغيير كلمة مرور أي مستخدم يلغي جلساته المفتوحة فوراً (رفع `token_version`).
- الحذف يُرفض إذا وُجدت بيانات مرتبطة، ويُطلب تأكيد صريح للحذف القسري.
- كل إجراء إداري يُسجَّل في `audit_logs` باسم المنفّذ ووقته.
- الصلاحية تُفحص في الخادم — أي طلب من غير مدير النظام يُرجع 403 حتى لو استُدعي مباشرة.

## 🚀 طريقة التشغيل (التطوير المحلي)

### المتطلبات
- Node.js v18+
- npm

### 1. تثبيت الاعتماديات
```bash
cd /path/to/rifad-platform
npm install
```

### 2. إعداد متغيرات البيئة (خطوة إلزامية)
انسخ ملف `.env.example` إلى `.env` ثم ولّد سرّاً عشوائياً قوياً:
```bash
cp .env.example .env
openssl rand -hex 32      # انسخ الناتج إلى قيمة JWT_SECRET داخل .env
```
ملاحظات هامة:
- المنصة **لا تعمل** بدون `JWT_SECRET` بطول 32 حرفاً على الأقل؛ لا يوجد سرّ افتراضي داخل الكود.
- لا تضع أسراراً حقيقية داخل `.env.example` أو داخل الكود المصدري.
- ملف `.env` مستثنى من Git ولا يُرفع إلى المستودع.

### 3. تهيئة قاعدة البيانات وبذر البيانات الأولية
```bash
npm run db:init
```
هذا الأمر ينشئ قاعدة البيانات `dev.db` من المخطط `prisma/schema.sql`، ثم يبذر المعايير السبعة و109 مؤشراً والمستخدمين التجريبيين.

> تُستخدم قاعدة بيانات SQLite محلية (`dev.db`) عبر `better-sqlite3` للتشغيل الفوري دون الحاجة لخادم PostgreSQL. المخطط المُصمم (`prisma/schema.prisma`) يقبل النقل إلى PostgreSQL عند النشر الإنتاجي.

### 4. تشغيل الخادم التطويري
```bash
npm run dev
```
ثم افتح المتصفح على: [http://localhost:3000](http://localhost:3000)

### 5. أول دخول
عند فتح المنصة لأول مرة، توجه إلى `/setup` لإنشاء حساب المسؤول الأول (مدير المنصة) بطريقة آمنة. بعد ذلك تدخل عبر `/login`.

#### حسابات الدخول التجريبية (للعرض الأول فقط)
تُنشأ تلقائياً عند تشغيل `npm run db:init`:
- البريد: `admin@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (مدير النظام)
- البريد: `director@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (مدير المديرية)
- البريد: `inspector@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (مفتش تربوي)
- البريد: `principal@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (مدير المدرسة)
- البريد: `quality@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (منسق جودة)
- البريد: `teacher@rifad.demo` — كلمة المرور: `R!f@d_2026_DemoAccess` (معلم)

## 🔐 الأمان
- كلمات المرور تُجزأ بـ bcrypt (تكلفة 12).
- رموز JWT قصيرة الأمد (وصول) وطويلة الأمد (تجديد) في كوكيز `HttpOnly`.
- إصدار الرمز (token version) يُ増 عند تغيير كلمة المرور لإبطال الجلسات القديمة.
- صلاحيات مطبقة في الخادم وقاعدة البيانات، وليس فقط إخفاء أزرار الواجهة.
- سجل تدقيق غير قابل للتعديل من المستخدمين العاديين.
- فحص نوع الملف وحجمه ومنع الملفات الخطرة.
- روابط وصول مؤقتة ومقيدة الصلاحية للملفات المرفوعة.

## 📄 التقارير والطباعة
- التقارير تُصدّر بصيغة PDF باتجاه RTL مع دعم الخط العربي (أميري).
- التصدير إلى Excel وCSV متاح مع معاينة قبل الطباعة.
- كل تقرير يحمل حالة: مسودة، قيد المراجعة، معتمد، أو مرفوض.
- رمز تحقق (QR / رابط آمن) لكل تقرير معتمد.

## 📱 العمل دون اتصال (PWA + IndexedDB)
- المنصة تُثبَّت كتطبيق ويب تقدمي: ملف `public/manifest.webmanifest`،
  أيقونات 192/512 وأيقونات maskable، وعامل خدمة في `public/sw.js`.
- عامل الخدمة يخزّن قشرة التطبيق (HTML/الأصول/الخطوط) ويعرض صفحة `/offline`
  عند تعذّر الوصول، ويستثني مسارات المصادقة والتحقق والتصدير من التخزين.
- درجات التقييم تُحفظ محلياً في IndexedDB (`src/lib/offline/drafts.ts`) عندما
  يفشل الحفظ على الخادم، وتظهر شارة «محفوظة محلياً» بعددها في صفحة التقييم.
- تُرفع المسودات تلقائياً عند عودة الاتصال، مع زرّ مزامنة يدوي.
- **ما لا يجري دون اتصال:** اعتماد التقارير وتغيير حالاتها وإدارة المستخدمين
  والصلاحيات — هذه كلها تتطلب اتصالاً بالخادم ولا تُنفَّذ محلياً أبداً.
- **حدّ معروف:** المزامنة ترفع التغييرات بالتسلسل ولا تحلّ تعارض تعديل
  المؤشر نفسه من جهازين (آخر وصول يفوز).

## 🛠️ ما يمكن للمدير إضافته من داخل الموقع

كل ما لم يُبنَ مسبقاً يمكن إضافته لاحقاً من لوحة الإدارة `/admin` دون تعديل الكود:

| ما تريد إضافته | من أين |
|---|---|
| مدرسة جديدة أو تعديل/حذف مدرسة | تبويب «المدارس»، أو استيراد Excel/CSV بفحص قبل الحفظ |
| محافظة / مديرية / منطقة | تبويب «المحافظات والمديريات» |
| مستخدم جديد أو تعطيل/قفل/إعادة تعيين كلمة مرور | تبويب «المستخدمون» |
| معيار أو معيار فرعي أو مؤشر جديد | تبويب «المعايير والمؤشرات» (مع الأدلة وأدوات التحقق والأوزان) |
| تعديل نص أي مؤشر أو أدلته | تبويب «المعايير والمؤشرات» |
| مستوى تقدير جديد أو حذف مستوى | تبويب «مقياس التقدير» |
| دور جديد بصلاحيات مخصّصة | تبويب «الأدوار والصلاحيات» |
| متابعة كل إجراء حسّاس | تبويب «سجل التدقيق» |
| نسخة احتياطية من قاعدة البيانات | زر «نسخة احتياطية» في رأس اللوحة |

**ملاحظة على الأدوار:** الصلاحيات الفردية تُمنح إضافةً إلى الأدوار الأساسية،
فهي تفتح وصولاً لدور جديد دون أن تُلغي ما تعرفه المنصة عن الأدوار المدمجة.
الشاشات الإدارية (المستخدمون، الأدوار، السجل، النسخ الاحتياطي) تبقى حصراً على
مدير النظام، ولا يمكن منحها لدور آخر — وهذا مقصود لمنع تصعيد الصلاحيات.
